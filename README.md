## 它在解决什么

A 股量化实盘，卡在三个地方：

**① 官方量化接口门槛高**
QMT / PTrade 动辄 50 万起的资金门槛，加上漫长的白名单审批。很多中小券商干脆不开这个口子。

**② GUI 自动化又慢又脆**
找图、点按钮、剪贴板粘贴——一笔委托 500ms 到 2 秒。更要命的是必须独占屏幕：一个弹窗、一次锁屏、分辨率一变，就是废单或者重复下单。

**③ 只能在 Windows**
手上是 Mac 或者 Linux 的，前两条都轮不到你，直接出局。

**a-ths-trade 把这一层整个换掉。** 不模拟点击，不碰屏幕，直接对接同花顺底层通道。

## 核心优势

| | |
|---|---|
| ⚡ **≈ 50ms 单笔委托** | GUI 模拟点击要 500ms~2000ms。快一个数量级。打板、抢筹、条件单触发，差的就是这几百毫秒。 |
| 🖥️ **跨平台原生** | macOS、Linux、Windows 都能跑。不再被"必须一台 Windows 机器开在前台"绑住，策略跑在服务器上也是它。 |
| 🎯 **非 GUI，不抢鼠标键盘** | 纯后台静默运行。不依赖屏幕分辨率，不依赖窗口焦点。你前台写代码、看盘、开会，它在后面下单。 |
| 🔌 **同花顺底层通道** | 走接口层，不走界面层。图像识别的全部不确定性——找错图、点偏、颜色变化、DPI 缩放——一次性消掉。 |
| 🔄 **天然多账户并发** | 没有"鼠标只有一个"这个物理限制。多账户、多策略、多标的可以同时跑，互不干扰。 |
| 🧩 **接口化接入** | 策略端按你自己的技术栈接。不绑定语言，不绑定框架，不绑定量化平台。 |

## 方案对比

| 对比维度 | GUI 自动化（找图 / 点击） | 官方量化接口（QMT / PTrade） | **a-ths-trade** |
|---|---|---|---|
| 单笔委托延迟 | 500ms ~ 2000ms | 10ms ~ 50ms | **≈ 50ms** |
| 运行系统 | 仅 Windows | 仅 Windows | **macOS / Linux / Windows** |
| 屏幕占用 | 必须独占前台 | 无需 | **完全后台，不抢鼠标键盘** |
| 资金门槛 | 无 | 50 万 ~ 500 万 + 审批 | **普通账户即可** |
| 多账户并发 | ❌ 物理上做不到 | 视券商版本而定 | **✅ 单机多账户并发** |
| 出错来源 | 界面层：弹窗、锁屏、DPI、配色 | 低 | **低，界面层不参与** |

## 适合谁

- **打板 / 抢筹** —— 成交与否由毫秒决定，人工和界面延迟都是纯粹的损耗

- **跨平台部署** —— 策略跑在 Linux 服务器或 Mac 上，不必专门养一台 Windows 当前台
