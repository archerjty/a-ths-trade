## 它在解决什么

A 股量化实盘卡在三个地方。

**① 官方量化接口门槛高**

QMT / PTrade 动辄 50 万起的资金门槛，加上漫长的白名单审批。很多中小券商干脆不开这个口子。

**② GUI 自动化又慢又脆**

找图、点按钮、剪贴板粘贴，一笔委托要 500ms 到 2 秒。更要命的是必须独占屏幕。一个弹窗、一次锁屏、分辨率一变，就是废单或者重复下单。

**③ 只能在 Windows**

手上是 Mac 或者 Linux 的，前两条都轮不到你，直接出局。

**a-ths-trade 把这一层整个换掉。** 不模拟点击，不碰屏幕，直接对接同花顺底层通道。

## 性能实测

### 单笔委托 50ms 级

端到端业务往返的实测样本，取的是**较慢的网络情况**。

| 分位 | 实测 |
|---|---|
| 最小 | **58.7 ms** |
| 中位 | **64.7 ms** |

拆开看这笔时间花在哪。

- **本地协议处理**，毫秒以下，在整笔耗时里可以忽略
- **网络往返（RTT）**，剩下的大头，**由你自己的网络环境决定**

所以这个数字是浮动的，不是一个固定承诺。上面这组实测对应的是**较慢的网络情况**。把策略部署到**上海或深圳**的服务器上，贴近交易所与券商网关，网络 RTT 大幅缩短，**实际会快很多**。

对照组，GUI 自动化方案 500ms 到 2000ms，而且那 500ms 是**屏幕操作**的耗时，网络往返还没算进去。

### 资源占用

图形客户端、Python 运行时、图像识别库、屏幕截图缓冲，这四样一个都不跑。

它们在传统 GUI 自动化方案里加在一起，**常驻内存通常在 1GB 以上**。本产品不需要其中的任何一样，这部分开销直接不存在。

## 方案对比

| 对比维度 | GUI 自动化（找图 / 点击） | 官方量化接口（QMT / PTrade） | **a-ths-trade** |
|---|---|---|---|
| 单笔委托延迟 | 500ms ~ 2000ms | 10ms ~ 50ms | **50ms 级** |
| 运行系统 | 仅 Windows | 仅 Windows | **macOS / Linux / Windows** |
| 常驻内存 | 图形客户端 + Python + 图像识别库，**1GB+** | 专用客户端常驻，数百 MB 级 | **无图形进程 / 无运行时** |

| 多账户并发 | ❌ 物理上做不到 | 视券商版本而定 | **✅ 单机多账户并发** |
| 出错来源 | 界面层，弹窗、锁屏、DPI、配色 | 低 | **低，界面层不参与** |

## 适合谁

- **私募**，需要在自有服务器上同时跑多个账户和策略的团队
- **打板 / 抢筹**，成交与否由毫秒决定，人工和界面延迟都是纯粹的损耗
- **条件单 / 网格 / 做 T**，触发即执行，不经过任何 GUI 环节
- **多账户分仓**，一套策略同时管多个资金账号
- **跨平台部署**，策略跑在**上海 / 深圳**的 Linux 服务器或 Mac 上，贴近交易所与券商网关，不必专门养一台 Windows 当前台

这套工具是给已经跑通实盘、手里有成型策略、并且自己管账户的人用的。私募和成熟的个人交易者上手最快。还在找策略，或者需要人带着一步步走的人，它帮不上忙。
